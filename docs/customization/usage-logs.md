# 日志与使用统计

当前前端按用途拆分日志展示，避免 API 请求、登录、充值和后台事件混在同一张使用记录中。数据库仍使用现有 `logs` 表，本阶段不增加物理分表或数据库迁移。

## 页面职责

### 使用记录

使用记录只包含以下请求流水：

- `Consume`：已结算的 API 请求；
- `Error`：转发失败的 API 请求；
- `Refund`：异步请求或任务结算产生的退款。

充值、订阅分配、兑换码、登录、管理员操作和系统事件不会出现在使用记录中。

页面按当前筛选范围展示：

- API 请求数、Token、用户扣费、请求成功率和精准计费覆盖率；
- 请求数、Token 或费用趋势；
- 模型和分组分布；
- 逐请求流水。

模型、分组、API Key 名称、用户和渠道筛选会读取当前时间范围内实际出现过的值，支持下拉选择和输入搜索。单类最多返回 200 个去重选项；仍可手动输入完整值进行精确筛选。普通用户只能获得自己的模型、分组和 API Key 名称，用户与渠道选项仅管理员可见。

汇总费用只统计 `Consume`，不会把退款或充值额度混入消费金额。成功率使用 `Consume / (Consume + Error)`；精准覆盖率只在已记录账单状态的消费请求中计算。

### 操作日志

管理员侧栏的“操作日志”分为：

- 登录活动：登录方式、用户、IP 和时间；
- 管理操作：管理员执行的用户、渠道、订阅和系统设置变更；
- 系统事件：安全验证、账号初始化和其他后台事件。

资金记录继续由钱包、充值和订阅页面负责展示，不进入使用记录或操作日志。

## 接口

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `GET /api/log/usage` | 管理员 | 查询所有用户的 API 请求流水 |
| `GET /api/log/usage/self` | 已登录用户 | 查询自己的 API 请求流水 |
| `GET /api/log/usage/analytics` | 管理员 | 按筛选范围汇总所有用户的使用统计 |
| `GET /api/log/usage/self/analytics` | 已登录用户 | 按筛选范围汇总自己的使用统计 |
| `GET /api/log/usage/options` | 管理员 | 获取当前时间范围内可搜索的使用日志筛选选项 |
| `GET /api/log/usage/self/options` | 已登录用户 | 获取自己的使用日志筛选选项 |
| `GET /api/log/audit` | 管理员 | 查询登录、管理操作或系统事件 |

原有 `/api/log`、`/api/log/self` 和统计接口继续保留，供兼容用途使用。

## 查询边界

- 使用统计单次时间范围最多 90 天；3 天以内按小时聚合，超过 3 天按天聚合。
- 模型和分组分布各返回消费最高的 8 项。
- 普通用户接口固定使用当前登录用户 ID，并忽略用户名和渠道筛选，不能越权查询。
- 管理员可按时间、模型、API Key、分组、用户名、渠道、请求 ID、上游请求 ID 和精准计费状态筛选。
